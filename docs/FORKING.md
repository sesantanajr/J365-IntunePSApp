*Português: [abaixo](#fork-mudança-de-marca-e-tradução).*

J365 IntunePSApp is MIT-licensed: you may fork it, change it, ship it under another name or build another product on it. The only obligation is to keep the copyright and licence notice ([LICENSE](../LICENSE)) and the attributions in [NOTICE.md](../NOTICE.md). Packages generated by the application contain PSAppDeployToolkit, which is LGPL-3.0: keep its licence files inside the package (they are copied automatically).

## What to change for your own edition

| What | Where |
|---|---|
| Product name, author, links, GitHub repository (used for the update check and the default database URL) | `AppInfo` in [`src/IntunePSApp/Core/Models.cs`](../src/IntunePSApp/Core/Models.cs) |
| Assembly name, version, company, copyright | [`src/IntunePSApp/IntunePSApp.csproj`](../src/IntunePSApp/IntunePSApp.csproj) |
| Logo and icon | `src/IntunePSApp/Assets` (`app.ico`, `app-256.png`, `j365-cloud.png`, `j365-logo.png`, and `author.jpg`, the photo of *Settings > About*) |
| Colours and fonts | The palette at the top of [`src/IntunePSApp/Styles.xaml`](../src/IntunePSApp/Styles.xaml) |
| Texts that mention the product by name | `src/IntunePSApp/Resources/Strings.*.json` (search for "J365") |
| Data folder and per-user install location | `AppPaths` in [`Core/Infrastructure.cs`](../src/IntunePSApp/Core/Infrastructure.cs) and `InstallService` |
| Curated application knowledge | [`catalog/curated.json`](../catalog/curated.json) |

The scripts copied to each package (`Publish-ToIntune.ps1`, `Sandbox-Test.ps1`) get the product name and repository of `AppInfo` automatically.

## Your own application database

The database is a single file, `catalog.json.gz`, plus `catalog-meta.json`. The workflow [`catalog.yml`](../.github/workflows/catalog.yml) builds both every day and uploads them to a release named `catalog` **of the repository it runs in**, and the application downloads from `https://github.com/<AppInfo.GitHubRepo>/releases/download/catalog/catalog.json.gz`. So a fork only needs to:

1. enable GitHub Actions on the fork and run *Update the application database* once;
2. set `AppInfo.GitHubRepo` to the fork.

Any HTTPS location works too (Settings > Application database > Update address), which is useful for an internal mirror.

## Adding a language

1. Copy `src/IntunePSApp/Resources/Strings.en.json` to `Strings.<code>.json` (for example `Strings.es.json`) and translate the values. Keep the keys and the `{0}` placeholders.
2. Register the file in `IntunePSApp.csproj` (copy one of the two `EmbeddedResource` lines, keeping `WithCulture="false"`).
3. Add the language to `Loc.Languages` and to `Loc.Resolve` in [`Localization/Loc.cs`](../src/IntunePSApp/Localization/Loc.cs), and to the language selectors (`SettingsView.xaml`, `MainWindow.xaml`).
4. Run `dotnet test`: the tests check that every language has the same keys and placeholders.

Curated notes and descriptions currently exist in English (`notesEn`, `d`) and Portuguese (`notes`, `dpt`).

## Seu próprio banco de dados

O banco é um único arquivo, `catalog.json.gz`, mais o `catalog-meta.json`. O workflow [`catalog.yml`](../.github/workflows/catalog.yml) gera os dois todos os dias e envia para uma release chamada `catalog` **do repositório em que ele roda**; o aplicativo baixa de `https://github.com/<AppInfo.GitHubRepo>/releases/download/catalog/catalog.json.gz`. Em um fork basta:

1. habilitar o GitHub Actions no fork e executar *Update the application database* uma vez;
2. apontar `AppInfo.GitHubRepo` para o fork.

Qualquer endereço HTTPS também serve (Configurações > Banco de dados de aplicativos > Endereço de atualização), o que é útil para um espelho interno.

## Adicionando um idioma

1. Copie `src/IntunePSApp/Resources/Strings.en.json` para `Strings.<código>.json` (ex.: `Strings.es.json`) e traduza os valores. Mantenha as chaves e os marcadores `{0}`.
2. Registre o arquivo no `IntunePSApp.csproj` (copie uma das duas linhas `EmbeddedResource`, mantendo `WithCulture="false"`).
3. Adicione o idioma em `Loc.Languages` e em `Loc.Resolve` ([`Localization/Loc.cs`](../src/IntunePSApp/Localization/Loc.cs)) e nos seletores de idioma (`SettingsView.xaml`, `MainWindow.xaml`).
4. Rode `dotnet test`: os testes conferem se todos os idiomas têm as mesmas chaves e marcadores.
